1. Проектирование программы ДПО с нуля: дифференциация под разные типы задач

+
Обучение через вызовТаксономия Блума Дифференцированное обучениеГеймификация
Контекст

Разработка 72-часовой программы ДПО для разнородной аудитории: инженеры и научные сотрудники с разным бэкграундом (от базового понимания данных до продвинутого уровня).

Задача

Спроектировать архитектуру программы с нуля, которая не «усредняет» материал, а даёт релевантные инструменты под разные профессиональные задачи, используя проектный подход.

Решение

• Архитектура на основе CBL и таксономии Блума: разбила программу на логические блоки с нарастающей сложностью — от формулировки профессионального вызова (уровни «понять/применить») до разработки прототипа и его прикладной адаптации (уровни «проанализировать/создать»).

• Дифференциация: разделила практический модуль на 2 трека в зависимости от типа данных:

— Технический трек: сенсорные данные, временные ряды, предиктивное обслуживание
— Исследовательский трек: табличные, текстовые и экспериментальные данные

• Смешанный формат и оценка: синхронные вебинары + асинхронная работа в LMS; балльно-рейтинговая система с укрупнёнными проектными заданиями; геймификация (бейджи, сквозной нарратив).

Результат

Участники решают реальные задачи из своей практики. Разделение на треки снизило когнитивную перегрузку и дало релевантный инструментарий инженерам и исследователям без взаимного замедления.

2. Редизайн программы на основе данных обратной связи

+
Проектирование на основе данныхУправление когнитивной нагрузкой СкаффолдингВходная диагностика компетенций
Контекст

По итогам анализа пилотного потока 72-часовой программы ДПО проведена итеративная оптимизация архитектуры и оценочных средств для повышения эффективности обучения.

Задача

Адаптировать структуру программы, сохранив учебные результаты и повысив прозрачность требований к участникам с разным уровнем подготовки.

Решение

• Оптимизация структуры: объединила разрозненные мини-задания в укрупнённые проектные этапы.

• 3 траектории: 1 с кодингом (Python) и 2 без кода (аналитика без кода, автоматизация без кода) — вместо запутанного разделения на 2 трека.

• Редизайн оценивания: базовый уровень (обязательный минимум) и продвинутый (опциональный вызов).

• Входная диагностика: чек-лист пререквизитов во вводном модуле.

Результат

Прозрачный маршрут под исходный уровень. Укрупнение заданий, три траектории и двухуровневая оценка снизили когнитивную нагрузку: новички на базовом минимуме, опытные — на дополнительных вызовах.

3. Разработка навигационных инструментов для самодиагностики

+
Входная диагностикаСамодиагностика СкаффолдингНавигация по программе
Контекст

На старте часть участников испытывала трудности с выбором траектории и оценкой своего уровня — ожидания расходились с реальной сложностью заданий.

Задача

Создать инструменты для самостоятельной оценки готовности к курсу и навигации по программе.

Решение

• Чек-лист пререквизитов: 14 критериев по 4 разделам; прогресс-индикация; блок «Если нет» с шаблонами; советы по разделам.

• Навигационные рекомендации: сценарии действий по итогам самопроверки.

Результат

Прозрачный инструмент оценки готовности до старта. Меньше уточняющих вопросов на старте, участники заранее видят «слабые места».

4. Разработка рубрик оценивания проектной работы

+
Обучение через вызовПроектное обучение Критериальное оцениваниеСкаффолдинг Двухуровневые заданияФормирующее оценивание
Контекст

Каждый участник работал над своим проектом — реальной задачей из профессиональной сферы. Нужна была объективная система оценивания с прозрачными ориентирами и поддержкой проектов разной сложности.

Задача

Разработать рубрики с чёткими критериями для разных типов проектов и разного уровня подготовки.

Решение

• Двухуровневые задания: базовый (обязательный минимум) и продвинутый (опциональный вызов).

• Рубрики: ключевые направления оценивания для каждого проектного задания.

• Шаблоны скаффолдинга: структурированные формы отчётов по этапам задания.

Результат

Прозрачные ориентиры качества и самооценка до сдачи. Шаблон отчёта снизил когнитивную нагрузку. Новички на базовом уровне, опытные — на дополнительных вызовах.

Как я работаю

Проектирую обучение так, чтобы оно решало рабочую задачу: от понимания аудитории до запуска, обратной связи и доработки.

1
Разбираю задачу
Для кого обучение, какая цель, какие ограничения по времени и уровню участников.
2
Собираю каркас
Модули, результаты обучения, траектории под разный опыт участников.
3
Наполняю практику
Задания, материалы и опоры для самостоятельной работы.
4
Делаю оценку прозрачной
Понятные критерии, уровни сложности, форматы обратной связи.
5
Смотрю на запуск и усиливаю
Собираю отклики и данные, упрощаю перегруженное, усиливаю то, что работает.

Давайте создадим крутое обучение вместе!
