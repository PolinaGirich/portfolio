1. Проектирование программы ДПО с нуля: дифференциация под разные типы задач

+
Обучение через вызов Таксономия Блума Дифференцированное обучение Геймификация
Контекст

Разработка 72-часовой программы ДПО для разнородной аудитории: инженеры и научные сотрудники с разным бэкграундом (от базового понимания данных до продвинутого уровня).

Задача

Спроектировать архитектуру программы с нуля, которая не «усредняет» материал, а даёт релевантные инструменты под разные профессиональные задачи, используя проектный подход.

Решение

• Архитектура на основе CBL и таксономии Блума: разбила программу на логические блоки с нарастающей сложностью — от формулировки профессионального вызова (уровни «понять/применить») до разработки прототипа и его прикладной адаптации (уровни «проанализировать/создать»).

• Дифференциация: разделила практический модуль на 2 трека в зависимости от типа данных:

— Технический трек: работа с сенсорными данными, временными рядами, предиктивным обслуживанием
— Исследовательский трек: работа с табличными, текстовыми и экспериментальными данными

• Смешанный формат и оценка: синхронные онлайн-вебинары с экспертами + асинхронная работа в LMS; прозрачная балльно-рейтинговая система с укрупнёнными проектными заданиями; элементы геймификации (бейджи за ключевые этапы, сквозной нарратив).

Результат

Участники решают реальные задачи из своей практики, а не абстрактные примеры. Разделение на треки позволило избежать когнитивной перегрузки и дало релевантный инструментарий как инженерам, так и исследователям, обеспечивая параллельную работу без взаимного замедления.

2. Редизайн программы на основе данных обратной связи

+
Проектирование на основе данных Управление когнитивной нагрузкой Скаффолдинг Входная диагностика компетенций
Контекст

По итогам анализа пилотного потока 72-часовой программы ДПО была проведена итеративная оптимизация архитектуры программы и оценочных средств для повышения эффективности обучения и адаптации под реальные потребности участников.

Задача

Адаптировать структуру программы, сохранив учебные результаты и повысив прозрачность требований к участникам с разным уровнем подготовки.

Решение

• Оптимизация структуры и темпа: объединила разрозненные мини-задания в укрупнённые проектные этапы.

• Перепроектирование дифференциации (3 траектории): вместо запутанного разделения на 2 трека выстроила чёткую структуру маршрутов — 1 траектория с кодингом (Python) и 2 траектории без кода (аналитика без кода и автоматизация без кода). Участники выбирают путь под свои навыки.

• Редизайн системы оценивания: формулировка задания с двумя уровнями сложности — базовый (обязательный минимум) и продвинутый (опциональный вызов).

• Входная диагностика: чек-лист пререквизитов во вводном модуле для самостоятельной оценки готовности.

Результат

Участники получили прозрачный и гибкий маршрут под свой исходный уровень. Объединение заданий, три понятные траектории и двухуровневая система оценивания снизили когнитивную нагрузку: новички фокусируются на базовых требованиях, опытные специалисты реализуют дополнительные вызовы.

3. Разработка навигационных инструментов для самодиагностики

+
Входная диагностика компетенций Самодиагностика Скаффолдинг Навигация по программе
Контекст

На старте программы часть участников испытывала трудности с выбором подходящей траектории и объективной оценкой своего уровня подготовки, что приводило к несоответствию ожиданий и реальной сложности заданий.

Задача

Создать инструменты для самостоятельной оценки готовности к курсу и навигации по программе.

Решение

• Чек-лист самопроверки пререквизитов: 14 критериев готовности по 4 разделам (идея проекта, данные, результат и проверка, готовность к старту); прогресс-индикация; для каждого пункта блок «Если нет» с шаблонами; практические советы по разделам.

• Навигационные рекомендации: сценарии действий по итогам самопроверки.

Результат

Участники получили прозрачный инструмент для самостоятельной оценки готовности до старта программы. Чек-лист помог снизить количество уточняющих вопросов на старте и заранее выявить «слабые места».

4. Разработка рубрик оценивания проектной работы

+
Обучение через вызов Проектное обучение Критериальное оценивание Скаффолдинг Двухуровневые задания Формирующее оценивание
Контекст

В рамках программы ДПО каждый участник работал над собственным проектом — решал реальную задачу из своей профессиональной сферы. Потребовалась система оценивания с объективностью проверки, прозрачными ориентирами качества и поддержкой проектов разной сложности.

Задача

Разработать рубрики оценивания для проектных заданий с чёткими критериями, которые работают для разных типов проектов и учитывают разный уровень подготовки участников.

Решение

• Двухуровневая система заданий: базовый уровень (обязательный минимум) и продвинутый уровень (опциональный вызов).

• Рубрики с прозрачными критериями: для каждого проектного задания прописаны ключевые направления оценивания.

• Шаблоны для скаффолдинга: структурированные формы отчётов, где участники фиксируют основные этапы задания.

Результат

Участники получили прозрачные ориентиры качества и возможность самостоятельно оценивать работы до сдачи. Шаблон отчёта и алгоритм выполнения снизили когнитивную нагрузку. Двухуровневая система позволила новичкам фокусироваться на базовых требованиях, а более опытным — брать дополнительные вызовы.
